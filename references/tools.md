## 一条真实片子的实测（功夫熊猫 4 石台场景，可当标定参照）

**素材**：4320×2160 / 24fps / 176 帧 / 7.33 秒 / 11.7Mbps / 192kbps。
**两个镜头**：f1–110 石台（希区柯克式），f111–176 大台阶变色龙坐轿。切点 **110/111**，检测 score 只有 6.5。

**镜 1 的最终参数（甲方确认"对了"的那一版）**：

| | f1 | f110 |
|---|---|---|
| 焦距 | **13.403mm 固定，不做动画** | 同左 |
| 机位 y | −5.15 | −3.70（前推 1.45m） |
| 机位 z | 1.92 | 2.01（人眼高度） |
| 俯仰 | 仰 1.4° | 仰 4.9° |
| 主角本地缩放 | 1.55 | **0.697**（比正常人还小） |
| 主角高度（站哪） | 0（地面） | 0.86（桌面，到 f75 才上去） |

**配角**：熊放大到 **1.263** 且站在主角正后方（x=0.035）——**它能从主角头顶露出来靠的是比主角高，不是机位**。

**这条片子的教训**：

1. 我花了两轮把焦距做成 30→18mm 的动画，方向就是错的。甲方要的"变广角"是**整条镜头就用超广角**。
2. 我一度把机位抬到 3.05m 去"让熊露出来"，完全是在解一个不存在的问题。
3. 主角占画面太大，我以为是机位太近，其实是**焦距不够广**。

**量出来的两个关键比值**：
- 主角屏幕尺寸 f1→f110 缩 **3.5 倍**
- 背景（两塔之间天空缺口）594px→331px，缩 **1.79 倍**
- 两个数不相等 → 主角本体在缩小，不是纯粹机位运动

## 灭点反解的做法

```python
# 两条线各取两端点，齐次坐标求交
line = lambda a,b: (a[1]-b[1], b[0]-a[0], a[0]*b[1]-b[0]*a[1])
vp = cross(line(p1,p2), line(p3,p4));  vp = vp[:2]/vp[2]

f_px   = lens * width / 36.0
pitch  = atan((vp[1] - height/2) / f_px)      # >0 表示相机上仰
yaw    = atan((vp[0] - width/2)  / f_px)
```

实测样例：原片 f110 桌面长边灭点 (627.8, 407.1)，画面 1280×640 中心 (640, 320)。
x 几乎居中 → 无偏航；y 偏下 87px → 上仰 8.7°。

## 相机投影约定（Blender）

- 相机局部空间看向 **−Z**；`rotation_euler.x = 90°` 是水平，**大于 90° 是上仰**（这个符号很容易搞反）
- 世界→相机要乘 R 的**转置**（R 是局部→世界）
- 传感器水平 36mm，`f_px = lens × width / 36`
